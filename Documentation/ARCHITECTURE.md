# Architecture

## MVVM with feature-based organization

The app uses **MVVM (Model–View–ViewModel) with a separate core/service layer**, implemented with SwiftUI Observation. It does not use MVC, MVP, TCA, or a global application state store.

- **Views** render state and forward user intent. Local `@State` is appropriate for transient UI details such as confirmation visibility, hover state, and cached drawing geometry.
- **View models** are `@MainActor @Observable` reference types named `…ViewModel`. They own presentation state, translate intent into service calls, and expose results for SwiftUI. They do not implement disk enumeration, SQL, or destructive filesystem operations.
- **Models** are the `Sendable` value types in `DiskCore`, including `FileNode`, `ScanRequest`, and `CleanupPlan`. They do not import SwiftUI or AppKit.
- **Core/services** own filesystem work, indexing, domain rules, and OS integrations. Actor isolation protects mutable core state. App-only adapters own security-scoped access, temporary scan storage, and Finder presentation.

The dependency direction is **View → ViewModel → Service/Core → value results → ViewModel → View**. `DiskCore` never imports the app target. The app entry point creates the workspace and injects its services; feature views receive their own view model and explicit action closures for cross-feature commands.

### Presentation ownership

| Owner | Responsibility |
| --- | --- |
| `WorkspaceViewModel` | Owns explicit screen phases, composes child models, coordinates scan/cleanup lifetimes, authorization handoff, automatic-selection previews and applies, shutdown, shared errors and Quick Look |
| `LocationSelectionViewModel` | Quick-target catalog, options presentation, and folder-drop validation |
| `ScanViewModel` | Scan configuration, pending/current location, real scan stages, progress, issues, index lifecycle and cancellation |
| `ExplorerViewModel` | Bounded map scenes and their queries, filters, scope, multiselection, four-scene cache, legend categories, folder history, breadcrumbs, curated hover descriptions; rejects stale sessions |
| `CleanupViewModel` | Deletion queue (normalized `CleanupEntry` list), operation state, results and cleanup-report presentation; applies automatic two-tier recommendations in bulk and delegates mutations to `CleanupServing` |
| `CleanupQueueModel` | Cleanup-queue panel projection: compact selected-first tree rows, lazy ancestor/child fetches, and local reveal/collapse state |
| `SettingsViewModel` | Suggestion preferences and their local persistence; the explorer reads the explicitly injected shared instance |

The workspace is an orchestration boundary, not a place to accumulate feature state. Do not add forwarding properties there solely to hide a child's ownership. `TreemapView`, `CleanupQueueView`, `ScanOptionsView`, `CleanupReportView`, and `SettingsView` consume focused models rather than the whole workspace. The workspace shell composes those features and owns their routing.

### Rules for future features

1. Add product behavior under `Features/<Feature>/Views` and `ViewModels`. Give a feature its own view model only when it has presentation state or behavior; simple reusable views need no empty model.
2. Put platform-independent domain logic and shared value contracts in the appropriate `DiskCore` subsystem. Put AppKit, bookmark, and app-container adapters under app `Services`. Keep feature-only helpers beside their feature; use `Shared` only for actual cross-feature presentation reuse.
3. Inject services at construction. Prefer small capability protocols such as `ScanServing`, `CleanupServing`, and `FilePresenting`; do not introduce a service locator, singleton feature models, or hidden sibling-model mutations. Cross-feature workflows go through explicit callbacks or the workspace.
4. Keep observable UI state main-actor isolated. Keep enumeration on its dedicated queue, SQLite state inside its actor, and expensive layout off the main actor. Cross-boundary data must be `Sendable`; do not suppress concurrency diagnostics to make a build pass.
5. Give tasks an owner, cancellation policy, and shutdown behavior. Invalidate pending queries when a session changes and check session identity after suspension. Wait for cleanup before closing its index or releasing grants.
6. Keep cleanup safety and filesystem accounting in core, even when a feature offers a new entry point. Preserve explicit confirmation, no Trash-to-delete fallback, protection rules, and unknown/partial scan semantics.
7. Keep previews/sample fixtures in `PreviewContent`; keep shipping resources in `Resources`. Preserve accessibility identifiers when reorganizing views.
8. Add behavior tests at the layer that owns the change, run core tests, verify a universal Release build, and compile relevant app/UI test targets. Document environment-blocked checks as unverified.
9. Update this ownership map, README links, project generator, and repository guidance when a feature changes the architectural boundaries.

## Module and concurrency boundaries

`DiskUnbloat` owns SwiftUI views, main-actor presentation state, bookmarks, Quick Look, and Finder integration. Standard macOS controls provide native materials, toolbar glass, focus, and accessibility; the map uses a clear data surface instead of stacked glass effects.

`DiskCore` contains Sendable value models, the scanner, SQLite actor, cleanup service, suggestion queries, and a pure squarified treemap layout. SQLite is the system library, not a downloaded dependency. Swift 6 language mode enables complete concurrency checking. Default isolation is not globally changed to MainActor; presentation classes declare it explicitly. CPU map layout uses `@concurrent` and the view's cancellable `.task` lifecycle.

## Scanning and storage

A single dedicated utility queue owns each Foundation directory enumerator. Requests for the next batch cross the queue using checked continuations; no task is created per file. Before deep enumeration begins, `ScanPermissionPreflight` runs on that same serial queue to touch any macOS TCC-gated directories (`Desktop`, `Documents`, `Downloads`, `Pictures`/`.photoslibrary`, `Music`/`.musiclibrary`, `Movies`/`.tvlibrary`, `Library/Photos`, `Library/Calendars`, `Library/Reminders`, `Library/Application Support/AddressBook`, `Library/Mobile Documents`, and container roots, plus `/Volumes/*` when cross-volume scanning is enabled) that lie inside the selected scan roots and are not excluded, so macOS presents all needed permission prompts upfront at scan start rather than interrupting a long home or root-disk scan minutes later. Batches contain at most 512 nodes, with a roughly 100 ms enumeration time budget between entries. A slow individual network filesystem operation can still block that worker until macOS returns it; cancellation is cooperative, never represented as instantaneous network I/O interruption.

The worker's `@unchecked Sendable` is limited to one private class. Its invariant is that all mutable enumeration state and error callbacks are used exclusively on its private serial queue. Follow-up: replace this bridge with a compiler-checked queue-backed executor when Foundation enumeration supports a suitable isolation contract; preserve serial confinement in any refactor.

The scan coordinator publishes at most five progress updates per second and retains a cancellation handle. Cancellation finishes the current batch, aggregates the partial index, and emits a final partial snapshot. The UI does not cancel its stream consumer prematurely. Inaccessible directories make their aggregate and root totals unknown. Discovered-byte progress is a subtotal, not a volume usage claim.

SQLite WAL transactions batch inserts; parent, known-size, and binary path indexes support bounded queries. Path-depth ordering permits bottom-up aggregation even when refreshed nodes retain old IDs. Raw sizes and indexed file categories are retained separately from counted sizes; initial aggregation assigns each hard-link identity one counted owner. Complete sizes remain nullable; known logical/allocated subtotals and unknown counts propagate separately so inaccessible descendants do not erase measurable bytes.

The explorer builds an immutable `MapScene` as its results canvas. Scene loading is breadth-first, capped at 10,000 entries, 256 direct entries per loaded branch, and three visible folder levels. Any omitted siblings are represented by an aggregate with exact combined known bytes and count. When the scene budget is exhausted, already-present folders remain atomic; their bytes are never dropped. Pixel-level aggregation further combines tiny entries. Folder frames are containment, not additional storage, so nested parent/child sizes are not summed for the root summary. Clicking an aggregate focuses its owner folder. While a scene loads (focus navigation, filter changes, folder refresh), a centered translucent pill with a spinner and the loaded folder's name appears over the map instead of the old small bottom-edge spinner; it never intercepts map clicks and its scale transition respects Reduce Motion, while the queue panel shows a compact matching "updating the list" readout in its header.

Filters use nonoverlapping file/package leaves, and current-subtree scope uses a case-sensitive indexed path range. The category legend only dims drawing and never changes the scene. Classification uses file extensions/metadata without reading contents. Map geometry is calculated off the main actor, and base Canvas drawing is isolated from hover/selection overlays. Focus transitions use a cached image rather than querying SQLite per animation frame. Four unfiltered scenes are cached per session. Only scene entries, explicit user selections, geometry and navigation IDs are held by presentation models; the filesystem hard-link identity set grows only with multiply-linked files.

`WorkspacePhase` drives choosing, scanning, preparing results, exploring, cancelled, and failed screens. Never infer screen routing from a progress snapshot. Scan setup options are a popover; picking an authorized target starts immediately. Reading, aggregation, and map preparation are real stages. The scan screen shows an approximate overall percentage and bar: discovered bytes over the volume's used space measured with one `statfs` call at scan start. It is an honest lower-bound approximation for subfolder scans, stays labeled as approximate, and shows 100% only when the scan completes or map preparation begins. Unreachable locations count and list live during the scan, not only after it. When the scan's root cannot be read at all, the failed screen names the underlying refusal — the first recorded issue (for example a macOS Files-and-Folders denial) — and offers *Reauthorize access*, which presents the system picker at the same location: macOS permission denials recorded from consent dialogs are only replaceable by fresh user-selected access, never by an entitlement. Decorative mosaic animation uses a paused TimelineView plus native phase animation and remains independent of the progress readout. Cancelled results require explicit opt-in, and cleanup remains disabled. The map owns the results canvas; there is no file browser or details inspector. The cleanup queue is the only side panel: a right-hand inspector that opens automatically once a completed scan reaches results and can be toggled from the toolbar. The minimum window is 960 × 640 once results appear; choosing and scanning live in a compact 660 × 640 window (content minimum 600 × 560) that regains the remembered full size when results return, and the scan layout compacts below 720 points high. The window never changes size in fullscreen.

Indexes live under process/session-specific directories in the app's Caches/Scans directory. They close and are deleted on replacement and orderly termination. Startup purges only directories whose owning process is gone, retaining entries when process inspection is denied; it never removes another live scan's index. Bookmarks and user preferences persist in local UserDefaults. Bookmark creation runs on a dedicated utility queue and must never block accepting a picker-granted location or delay scan setup. A save/refresh failure produces a nonfatal notice; the current session remains usable. Bookmark resolution also runs off the main actor, and revoked saved access requires choosing the location again. Only successful security-scope starts are balanced with stops. No scan history is retained.

## Filesystem semantics

ScanRequest retains the exact picker/bookmark URL, including its security-scope association; never rebuild the authorization URL from a path. The enumeration worker separately canonicalizes the indexing path using realpath because Foundation can expose both /var and /private/var aliases. Symbolic links are recorded with lstat and never traversed. Hidden entries are included unless excluded. Packages are always enumerated for accounting but presented atomically by default. Cloud-only iCloud directories are left unenumerated and marked incomplete; file contents are never opened by the scanner.

Grouped quick actions scan several known home locations in one pass. `ScanRequest.extraRoots` lists additional roots and `groupTitle` names a synthetic wrapper node (`ScanGroup.path`) that becomes the map root; every real location is inserted beneath it, one after another, each with its own enumerator and cross-volume device check. The wrapper is never a filesystem path: it cannot be previewed, cleaned, or branch-refreshed (refreshing it reruns the entire grouped scan), and an unreadable location is recorded as an issue while the scan continues with the next one — the scan fails only when every listed location is unreadable. `ScanViewModel` keeps the combined scope so a post-cleanup rescan repeats the whole group, and `prepareRefresh` accepts folders inside any listed root. `CleanupPlan.roots` carries the full scope list; lexical, managed-data, and system-tree checks then apply within every listed root. Grant retention (`AuthorizationStore.retainOnly`) keeps every grant covering any scan root, and a grouped target reaches the chooser only after the home grant (or an equivalent saved location) covers all its roots; otherwise the picker suggests the home folder. Restoring coverage prefers the most specific covering stored bookmark (`coveringLocation` — the home grant over a broad volume-root bookmark such as `/`, whose activation does not reliably extend the sandbox into protected home data), and both grouped and single quick targets run this restore before falling back to the picker, with the reuse failure visible as a "choose the location again" message. With that same reasoning the scan task revives the covering grant headlessly (`ensureGrant`) when a home-rooted scope cannot be opened — the sandbox denies openings without an active security-scope grant even while metadata stays readable — and never shows a picker from inside the flow: an unrepairable scope lands on the failed screen, which names the recorded refusal and offers Reauthorize access. Branch validation and replacement skip the synthetic wrapper when walking ancestors.

Logical and allocated sizes are distinct; missing values remain unknown. Hard links contribute once within the selected scope, so another link may show zero counted bytes. APFS clones can share extents without sharing inode identity; clone/snapshot/purgeable accounting is not represented as exact reclaimable space. Directory timestamps describe the directory itself, not its descendants' usage. No access-date based claim of “unused” is made.

## Cleanup

The cleanup queue is the canonical selection list, rendered as the right-hand `CleanupQueueView` panel. It removes duplicate and overlapping selections. Scan roots, system trees, and package internals are blocked from removal; a scan-root folder — a listed location of a grouped target or the root of any single-root scan — can instead be queued to empty its contents while the folder itself stays (`/` and volume roots remain refused, and the managed-data, package, and system protections still apply to the folder and inherit to its contents). Regular third-party app bundles placed directly inside `/Applications` are the one system-tree carve-out: the folder itself, `/Applications/Utilities`, grouping folders, nested content, and non-package direct children stay system-managed, while a direct `.app` package is treated as the user-installed application it is (macOS still refuses Apple-pinned apps itself, and per-item failures are reported). Each queue entry carries its operation (`.remove` or `.emptyContents`); plan normalization keeps the topmost entry, subsumes anything queued inside a kept entry, and prefers removal for the same path. Managed application data stays blocked except for the exact curated cache locations declared by `CleanupRule`: the location itself and its contents may join the queue while its managed parents and every other managed tree remain protected. The exemption travels on `CleanupPlan.knownCacheRoots`, so the queue's checkbox add path, the plan preflight within core, and the hover-card safety guidance all agree. Whole ordinary user-owned packages outside protected trees can be reviewed. Cache candidates always carry an explanation of application disruption risk.

The queue panel, titled "Select items to delete", renders the currently open folder's direct children ordered by known size descending — even when the queue is still empty, so items can be selected right there; the listing pages with an honest total and `Show more items`. An unselected plain folder can be expanded to peek at its three largest children (largest first, with `Show more items` paging the rest); packages stay atomic unless inspection is on. Map selection and panel rows mirror each other: tapping a panel row highlights the same tile on the map, and a map selection highlights the matching panel row (expanding the folder chain lazily — paging folders whose target child lies beyond the first page, opening collapsed folders and covered containers on the way — and scrolling it into view). The panel's map-selection highlight is independent of the queue checkboxes. Panel rows carry the map's context menu (Focus folder, Rescan folder, Quick Look, Reveal in Finder, Copy path, and Select/Deselect mirroring the row's checkbox), and a small button in the panel header clears the whole selection at once — manual and recommended picks alike — while the last operation's report stays. The panel has exactly two sections: the open folder's listing (everything in its subtree nests there — for the synthetic group wrapper that is the whole scan, since real paths are never lexically "within" the synthetic path) and the compact selected-first tree for entries strictly outside it; a row is rendered exactly once. Below it, normalized entries elsewhere in the scan keep their compact selected-first tree: a fully selected folder is one atomic checkbox row (its contents disappear with it); a partially selected folder appears expanded with selected children first and unselected siblings hidden behind a `… N more items` control that lazily fetches direct children in name order. An entry selected below the listing nests under its folder's row instead of appearing twice. Partial rows show only the selected bytes with the folder's known total after a slash ("5.2/50 GB"; suppressed when the selected subtree already equals the folder's total or the total is unknown), entries show their known size, and the total uses `knownSize(for: .allocated)` on normalized entries — the same accounting the map subtracts, so it stays an estimate, never a reclaim promise. Tri-state checkboxes mean checked (entry), partial (clicking selects the whole folder; when that selection is refused — for example a running application's cache among the queued children — the click clears the entries already queued inside the folder instead, with the refusal and the deselection stated in the alert), and unchecked (clicking selects); unchecking removes the covering entries. The panel's `Delete Selected` button runs the existing confirmation flow — Trash first, permanent deletion behind a second, stronger confirmation — and never falls back from Trash to permanent deletion. Curated item descriptions live only in the map hover card: `LocationCatalog.knownLocations` (`Features/LocationSelection/Models`) matches a node's path against curated locations, first match wins, so more specific entries stay earlier in the list; parent-level explanations for broad tool trees (Homebrew, the Android SDK, `.android`, `.npm`, `~/go`, `.local`, `.rustup`, `.gemini`, `Library/Application Support` and the Steam tree) and the absolute `/System/Library/AssetsV2` description are appended after them and shadow nothing. These descriptions are explanations only — they never become cleanup rules, and the chooser's quick targets derive separately from `CleanupRule`. Queued items disappear from the map through `FileQuery.hiddenPaths` and reappear when they are removed from the queue or deleted; a container whose every child is queued collapses to one `hiddenSubtrees` range (`ScanIndex.coalescedHiddenRanges`), which hides its descendants while the folder itself stays visible. The queue is the single source of these hidden paths: every queue mutation reaches the explorer from the model layer (`CleanupViewModel.basketDidUpdate` → `explorer.updateHiddenPaths`; a view-side `.onChange` relay silently never fired for big selections and is gone). The hidden application reloads the scene synchronously after the coalescing lands, because the debounced query can be cancelled by unrelated activity and once left a stale map with no way back. At any realistic scale (a rebuildable quick-select queues well over a thousand entries) a per-path clause list cannot represent the exclusions: past SQLite's expression-depth limit the whole statement fails silently and the map blanks. `ScanIndex` therefore materializes the excluded row ids once per exclusion state (`excludedRow`, filled through indexed path-band scans) and every query rejects excluded rows with a primary-key anti-join — no expression-depth or statement-length limits, no per-row range probing; the tables are rebuilt whenever the query's exclusion state differs from what they hold, including the emptied state, and the per-path clause fallback remains for connections that refuse temp tables. Fully collapsed containers subtract the queued children's known sizes from their own tile and every ancestor (`queuedChildBytes`, bucketed once per commit into an ancestor-keyed dictionary so per-row subtraction is O(1)), so the map total equals the scan minus the queue's estimate; a queued item's map selection leaves the selection. Panel-and-map membership tests use the queue's rebuild-per-change index (`QueueMembershipIndex`, O(depth) walks) rather than a linear scan per render, and the queue's `estimatedBytes`/unknown flags are cached per basket change. Bulk-scale gathers batch their work: the panel resolves every queued chain's ancestors in a constant number of indexed `id IN` statements (`CleanupQueueProviding.ancestors`), partial-ancestor detection is set-based with an entries-id set, and child counts for whole folders arrive grouped in one statement. The listing's access shape (`parent=? ORDER BY knownAllocated DESC, id LIMIT n`) is served by a composite `parent_size_index`, without which SQLite plans a full single-column size-index scan per folder.

The queue panel's quick-select buttons apply one closed, path-based rule set (`Suggestions/AutoSelection.swift`; `AutoSelectionSpec` derives its cache side from `CleanupRule.userCaches` and lists its developer side explicitly) inside whatever the scan covers — the "Dev tools"/"All caches" behavior is a scope intersection, never a per-group branch. Tier 1 (safe) selects Xcode Derived Data and known regenerable caches in full, previous device-support versions for iOS, watchOS, tvOS, and visionOS (keeping the newest), previous simulators (keeping the two newest), one previous build of every automation-browser family (Playwright), previous Cypress and Gradle-distribution versions (keeping the newest), previous Godot export-template versions (keeping the newest), Android previous system-images and NDK (keeping the newest), long-unused Android virtual devices (never the newest; each `.avd` folder carries its `.ini` sidecar), long-unused LM Studio store children (both the legacy `.cache/lm-studio` and the modern `~/.lmstudio` layout), long-unused Hugging Face hub/datasets models (`~/.cache/huggingface`, auth tokens never eligible) plus its xet transfer cache in full, long-unused PyTorch (`hub`, TorchInductor kernels), MLX, and Whisper model children, Triton's compiled-kernel cache in full, Unreal's shared Zen-store children (`Epic/UnrealEngine/Common/Zen/Data` — local DDC plus cooked output, all derived from project assets, guarded while any Epic-owned app runs), ComfyUI Desktop's Electron caches, the editors' Chromium caches, act's downloaded-action cache in full, the Telegram media cache folder the wildcard resolves per account (media re-downloads from the chat; the whole-container delete that also logged users out is gone), and long-unused CLIP and Keras (`models`/`datasets` eligible) model children; the live `~/Library/Caches` tree is the one location tier 1 never touches. Tier 2 (rebuildable) covers those locations in full, adds all of `~/Library/Caches`, adds the extracted Go module trees (`~/go/pkg/mod`, the download cache exclusively for tier 1), the tier-2-only polyglot package stores (pnpm store variants, NuGet packages, the Dart pub cache, Minikube's download caches), Ollama's `models` tree (the `id_ed25519` keypair and the rest of the home stay structurally unreachable), Unity's downloaded Asset Store archives, the Conda package caches, the default self-hosted Actions runner's tool and action caches (`actions-runner/_work/_tool`, `_actions`), and `CacheClip` render-cache folders under the media storage, plus the name-matched and sibling-verified rebuildable folders (`CleanupRule.regenerableNames`/`regenerableManifests` — including Godot's project-local `.godot` cache and Unreal's `Intermediate`/`DerivedDataCache` folders, which match only beside a `.uproject` or `.uplugin` descriptor); container and Linux-VM runtimes (OrbStack, Colima, Lima, Podman, Minikube's VM), Maven's local repository, and Xcode's signed release Archives stay scan-only and are never auto-selected; clicking tier 2 first shows a warning with an honest estimate, and both tiers still end at the existing deletion confirmations. "Previous versions, falling back to long-unused when a location has no previous versions" and "long-unused" are defined by the subtree's latest recorded content modification against the scan's `longUnusedDays` threshold (default 90, edited with the scan options, consumed at selection time so no rescan is needed); the single most recent version of a keep-newest location is always preserved — the long-unused fallback never takes it; missing dates and incomplete sizes never establish eligibility, and no access-date claim is made. Locations whose children mix caches with user-authored content (LM Studio's `chats`, `conversations`, `config-presets` in both store layouts, Hugging Face's auth-token files, PyTorch's unknown sibling folders) carry a closed eligible-name list (`AutoSelectionRule.eligibleChildNames`): user content can be neither regenerated nor restored, so it is never selected in either tier and unknown future children stay out until added deliberately. Recommendations apply in bulk: every proposed node passes the same `CleanupSafety` and running-application checks as manual selection (refusals are counted, never forced), a fully covered scan root becomes one "clean contents, keep folder" entry, and a new recommendation replaces the previous one while manual picks stay. A fully queued container renders as one atomic kept-folder row, collapsed by default with its individual entries behind its chevron, and panel totals still derive only from normalized entries.

Before each serial operation, cleanup verifies lexical scope, canonical parent ancestry, indexed ancestor identities, leaf identity, ctime/size/mode fingerprint, and parent write access. A changed item is skipped. An emptied scan root is validated the same way (folder identity/fingerprint and write access on the folder itself), then each of its current direct children is removed with the plan's mode; the injected async preflight — a path-based running-application guard — is rechecked before every child, mounted-volume children are never swept, and any child that fails stays in place while the run continues. The folder itself is never deleted. Trash uses FileManager's Trash operation and never falls back to permanent deletion. FileManager performs explicit permanent deletion only after the separate UI confirmation. A full rescan after successful cleanup recalculates links and all aggregates. Folder refresh is a separate transactional operation with reviewed-basket invalidation. Every execution also emits an ordered `CleanupEvent` trail through `CleanupPlan.diagnostics` (queue, per-item outcome, per-child failures inside emptied folders); the app persists it through `Services/Diagnostics/CleanupDiagnosticsService` as JSON lines appended to `~/Library/Logs/DiskUnbloat/cleanup.log`, framed by run-start and run-finished summaries, so a post-mortem shows exactly which paths failed and why. Write failures are swallowed — diagnostics never break cleanup — and tests and previews inject a no-op recorder.

These are point-in-time checks. Foundation does not provide an atomic “delete this exact scanned inode and all its unchanged descendants” transaction. Concurrent filesystem changes can occur after validation, and selected folders include their current contents. Do not describe this as protection against a hostile process racing filesystem mutations. The app must not be marketed as an automatic cleaner or secure eraser.

## Focused refresh and storage analysis

`ScanViewModel` retains the live index while a folder refresh enumerates into a separate staging database under the same session store. It derives the child request from the original authorized URL and reuses the scan's original options. Refresh validates indexed ancestry before enumeration and again before commit. Cancel/failure discards staging and offers the previous map; the short atomic commit is not cancellable. A partial refresh replaces stale children with the known current subtree and explicit incomplete metadata.

`ScanIndex.replaceBranch` attaches the closed staging database and performs one SQLite transaction. IDs survive only for matching path plus filesystem identity; a high-water counter prevents reuse of deleted IDs. It recalculates counted bytes for affected identity groups across the full index and aggregates refreshed directories and affected ancestors in depth order. It transfers branch issues and increments the index revision atomically. Other branches retain their original snapshot semantics; refresh makes no claim that the entire filesystem is current.

`ScanIndex` remains one actor but is split across focused files in `Indexing/` so each concern stays navigable: `ScanIndex` (connection, schema, and module-internal row readers/binding helpers), `ScanIndex+Write` (insert, aggregate, issues, remove), `ScanIndex+Query` (the decomposed `FileQuery`→SQL `predicate` clause builders, summary/category queries, the map snapshot, and the cleanup queue's bounded child reads), `ScanIndex+Refresh` (validate/replace branch, ancestry), and `ScanIndex+AutoSelection` (the two-tier quick-select candidates and the hidden-range collapse). Path-relationship and prefix-range checks share the `String.isWithin(_:)`, `.overlaps(_:)`, and `.pathRange` helpers in `FileSystem/PathScope`.

`ExplorerViewModel` owns filters, selection, statistics, and navigation restoration, plus this scan's queued-item hiding (`updateHiddenPaths`). It invalidates pending tasks before refresh, keys scenes by index revision, restores surviving IDs/history, and falls back to a surviving ancestor. The workspace removes overlapping basket entries, including selected ancestors, so updated contents require review. Session storage deletes only the discarded database and its sidecars, never a live sibling staging/main index. Query construction (`sceneQuery`/`legendQuery`) lives in the `ExplorerQueries` value type; the view model snapshots its state through `makeQueries()` and keeps only orchestration and the scene cache.

`CleanupQueueModel` turns the normalized queue plus the open folder into panel rows: it lists the current folder's direct children in bounded size-ordered pages, resolves each entry's ancestors from the live `ScanIndex` through the injectable `CleanupQueueProviding`, counts direct children for honest hidden badges, fetches revealed unselected siblings in bounded name-ordered pages, and lazily pages the three-largest peek of expanded unselected folders. All of that is read-only; every mutation still goes through `CleanupViewModel` and core cleanup safety. Queued rows keep their own reveal/collapse/peek state, and the panel's totals are computed from normalized entries only — never from a map scene or a rendered row. Category highlighting only dims the map.

`CleanupRule` has stable bundled identifiers. Candidate SQL evaluates size, explicit `CleanupRoot` lists, descendant modification maxima, completeness, and exclusions. Each root declares a candidate mode: `rootItself` contributes the cache location folder itself, `children` contribute disjoint direct children (leaf candidates when the root is not part of the scan), and `childrenKeepingNewest` excludes the subtree of the most recently used direct child instead of applying the age cutoff. The user-caches rule spans ~/Library/Caches, Xcode Derived Data, old iOS/watchOS/tvOS/visionOS device support and simulator devices (newest kept), simulator-side throwaways (runtime caches, SwiftUI preview devices, and leftover test clones), Gradle wrapper distributions, and explicit application cache locations such as game, browser, editor, messenger, and automation-browser caches, Rust's Cargo registry/git caches, bun's package cache, uv, gradle, Adobe's shared media/Peak/PTX cache, Unreal's shared Zen store, Godot's export templates (never `app_userdata`, where `user://` game saves live), Unity, DaVinci Resolve's Fusion cache, Figma, ComfyUI Desktop's Electron caches, Terraform/sccache/Composer/Ivy/Deno caches, Steam's six curated stores (app/HTML caches, depot, partial downloads, update staging, and per-game shader folders — never `steamapps/common` installs, workshop content, or the `userdata` cloud saves), act's action cache, and the message-app stores' per-account media — a `CleanupRoot` wildcard (`stable` + `account-*/postbox/media`) resolves against the real filesystem at call time, so only existing Telegram accounts' media folders are candidates and the container (login, account data) is never a root (never `~/.cargo/bin`, `~/.bun/bin`, or the editors' `User/` settings trees, which hold user content). The regenerable rule matches cache-like directory names — node_modules, Pods, DerivedData, .cache, .build, `.next`/`.nuxt`/`.svelte-kit`/`.astro`/`.turbo`/`.vite`/`__pycache__`/`.pytest_cache`/`.tox` and the rest of the closed `CleanupRule.regenerableNames` list, with `.derivedData*` as a name prefix — anywhere in the scan without age gating, tier-2-only, so ordinary folder scans can highlight the best deletion candidates. Context-dependent names join `regenerableManifests`: a `target`, `.venv`, `venv`, or Unity `Library` folder matches only when a correlated sibling check against the parent's real children proves its project context (`Cargo.toml`/`pom.xml`, a Python manifest, or `Assets`+`ProjectSettings` together), and Unreal Engine's `Intermediate`/`DerivedDataCache` match only beside a `.uproject`/`.uplugin` descriptor, while Godot's `.godot` project cache is distinctive enough to match by name. The same names can never shadow hand-written or versioned content. Large files default to 1 GB, downloads/archives to 180 days, caches to 30 days. Missing dates/incomplete sizes cannot establish age-based eligibility. App-only `ApplicationActivityProviding` identifies running bundle-owned caches, Xcode Derived Data, and the running editors'/browser's/Adobe-video-suite's/Telegram's/Steam's/Unreal-or-Epic-owned/Godot-owned/Comfy Desktop's curated cache locations; it cannot establish that arbitrary command-line tools are idle — and Unity, Resolve, and Figma's caches ship without a running-app guard because no bundle ID could be verified from primary sources (documented; each cache regenerates regardless). Known active/protected caches are excluded at query/review time and checked again before each serial mutation through an injected async preflight (path-based, so an emptied scan root rechecks every child). An active cache among a root's contents does not block queueing the root for cleaning; a root that is itself an active cache stays refused. `CleanupReason` provides typed protection reasons; UI strings remain presentation concerns.

`MapNavigationAdapter` confines AppKit event monitoring to the active map/window. It recognizes horizontal trackpad movement and extra mouse buttons, ignores momentum and vertical/diagonal scrolling, and removes its monitor on detachment. SwiftUI's completed magnification gesture focuses a folder at 1.15 or navigates upward at 0.85. No global monitor or accessibility entitlement is used.

`AppDelegate` buffers native open-file events until workspace attachment, then routes them through the same single-directory authorization flow. Info.plist registers folders/volumes as alternate Viewer types. Busy requests report an error rather than queuing a surprise scan. Knowing a path still does not grant access; insufficient access routes through the system picker.

A successful child-branch refresh does not make a previously cancelled whole scan complete or enable its cleanup. Only a completed scan of the original root can do that.

English and Russian shipping strings live in `Resources/Localizable.xcstrings`, with explicit Russian plural categories. `Shared/Localization` maps stable domain values to display strings; `DiskCore` remains independent of SwiftUI/AppKit and localization bundles. Filenames, paths, bookmarks, enum identifiers, and SQL values are never translated. Follow macOS app-language preferences; do not add a second language setting. Run `Tools/audit-localization.py` after changing UI text, optionally passing compiler-generated stringsdata to verify extraction coverage.
