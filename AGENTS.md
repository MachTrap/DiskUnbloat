# DiskUnbloat contributor guidance

Read `Documentation/ARCHITECTURE.md` before implementing or reorganizing a feature. It defines the MVVM ownership map, directory tree, dependency direction, concurrency boundaries, and safety rules. Keep that document current when these boundaries change.

## Required structure

- App entry point, lifecycle and entitlements: `DiskUnbloat/App`.
- Product features: `DiskUnbloat/Features/<Feature>/Views` and `ViewModels`.
- App-only OS adapters: `DiskUnbloat/Services/<Capability>`.
- Actually shared presentation utilities: `DiskUnbloat/Shared/<Purpose>`.
- Assets/privacy manifest: `DiskUnbloat/Resources`; previews/generated samples: `DiskUnbloat/PreviewContent`.
- Domain models and filesystem/indexing/cleanup/layout logic: the matching subsystem under `Packages/DiskCore/Sources/DiskCore`.
- Core behavior tests: `Packages/DiskCore/Tests/DiskCoreTests`; app presentation tests: `DiskUnbloatTests`; UI scenarios: `DiskUnbloatUITests`.

## MVVM boundaries

Use `@MainActor @Observable` classes named `…ViewModel` for presentation state. Views render state and invoke intent methods; local confirmation/hover/layout state can remain in the view. Inject services rather than constructing them inside views. Keep core independent of SwiftUI/AppKit and the app target.

`WorkspaceViewModel` composes feature view models and coordinates cross-feature workflows and shutdown. Keep chooser/quick-target/drop state in `LocationSelectionViewModel`, scan state in `ScanViewModel`, query/navigation/selection state in `ExplorerViewModel`, queue/operation state in `CleanupViewModel`, cleanup-queue tree rows and reveal state in `CleanupQueueModel`, and preference state in `SettingsViewModel`. Pass focused models or values and action closures to child views. Do not grow the workspace into another all-purpose model or add redundant forwarding state.

Keep blocking enumeration on its dedicated queue, indexing inside its actor, and expensive layout off the main actor. Preserve Sendable contracts, task ownership, cancellation, query-session invalidation, and balanced bookmark/scope call pairs (the app is unsandboxed, so scope calls are no-ops and TCC consent governs access). Do not add unchecked concurrency annotations without a documented invariant and migration follow-up.

Preserve cleanup protections, identity/fingerprint/ancestry validation, explicit review and irreversible-action confirmation. Never fall back from Trash to permanent deletion. Do not equate age or size with safe deletion or promise unrestricted disk access/exact reclaimed space. Scan roots are never removed; queueing one empties its contents while the folder stays (`/` and volume roots stay refused), and the per-child preflight still guards running-application caches before every removal. The only system-tree carve-out is regular third-party app bundles placed directly inside `/Applications` (removable like home-folder apps); everything else under `/Applications`, package internals, and managed data stay protected.

## Project maintenance and verification

After adding or moving app Swift files, update matching Xcode groups and build membership. `python3 Tools/generate-project.py` recursively regenerates the checked-in project (`DiskUnbloat.xcodeproj/project.xcproj`, the Xcode 27 JSON format, which requires Xcode 27 or later and is canonicalized with Apple's `xcprojformatter`); it discovers app and test sources recursively, and preserves any owner-configured signing/team/bundle settings when editing or running the generator. The file uses JSON5-style trailing commas, so scripts that read it must use a JSON5-tolerant parser, not plain `json.loads` or `jq`. Resource and entitlement paths must remain correct. SwiftPM discovers nested core files automatically.

The app target signs **Manual** with the owner's Apple Development certificate (`DEVELOPMENT_TEAM` = the certificate's OU, `24Q556TG24` — Xcode matches teams by OU, not the CN suffix; Automatic style rejects the unified certificate on macOS targets). Never revert the app target to ad-hoc signing: TCC binds Full Disk Access grants to the binary's designated requirement, and an ad-hoc requirement pins the exact cdhash, so every rebuild would silently revoke the user's grant. Test targets stay Automatic (they run with `CODE_SIGNING_ALLOWED=NO`).

Run `swift test --package-path Packages/DiskCore`, a generic macOS Release build, and relevant app/UI test compilation after structural changes. Add tests for changed behavior, especially asynchronous session replacement and cleanup. Never perform destructive tests on user-selected files; use unique generated fixtures. Record unrun or environment-blocked validation honestly in `Documentation/VALIDATION.md`.

## Agent Testing target (AgentDevKit)

`DiskUnbloatTesting` is a Debug-only build of the same sources plus `DiskUnbloatTesting/`, linking the local AgentDevKit package (`../../AgentDevKit`, or `AGENTDEVKIT_PATH`). The generator adds it only when that package exists, so a clone without it still builds the shipping app. It has its own bundle ID (`com.diskunbloat.app.testing`: separate defaults and a clean TCC state), an isolated `TestingProfile` for scan indexes and a generated fixture home, a dry-run cleanup service that never moves or deletes anything, and a compile-time `#error` outside Debug. Shipping targets never contain bridge code: the Release audit (`nm`/`otool -L` on `DiskUnbloat.app`) must find no AgentDevKit symbols.

Run `Tools/agent-testing.sh [--fixture sample-home|dense-map|permission-wait] [--real-home]`, then drive it with `agentdevctl --session com.diskunbloat.app.testing` (`fixtures load`, `state`, `action invoke`, `ui capture`, `ui tree`). Fixtures generate real trees and run the real `ScanCoordinator`; adapters read production view models and call their intent methods only. Use it to verify UI and behavior changes in the running app instead of describing them as unverified. TCC experiments use `--real-home` on the Testing bundle ID only, never a reset of the shipping app's grants.

## Native macOS app verification policy

Build success alone does not establish correctness for behavior or UI changes. The full toolchain, route map, and workflow live in `Documentation/AGENT_NATIVE_MACOS_DEVELOPMENT_GUIDE.md`; the rules that cost nothing to follow and directly prevent wasted agent work are:

1. Use the documented build and verification path — `python3 Tools/generate-project.py`, `swift test --package-path Packages/DiskCore`, hosted suites (`xcodebuild … -only-testing:DiskUnbloatTests`), and the universal Release build. Never rediscover scheme, bundle ID, or derived-data layout per task.
2. Reproduce reported defects in the real flow with deterministic model-level suites (e.g. `MapAfterSelectionTests`) and, when the sandbox or a real scan is essential, env-gated test-host probes — not by re-clicking UI navigation for every attempt.
3. Probes and debug routes exercise the production models, coordinator, and views. Never verify behavior through a synthetic clone of a feature.
4. Preserve stable, semantic accessibility identifiers (`chooseLocation`, `queueCheckbox`, `reauthorizeFailed`, …). New controls get IDs; accessibility text stays localized.
5. Cache stable facts (scheme, bundle ID, commands, phase map). Never cache process IDs, window IDs, accessibility snapshot IDs, or element coordinates across runs.
6. State a reproduction with an expected observable outcome before editing; after editing, re-run the same probe/fixture and compare state, not vibes.
7. A dispatched action is not proof of success: observe updated model/UI state before continuing, and never blindly repeat a non-idempotent operation (deletion, cleanup execution, scan restart).
8. Search narrowly (`rg` on symbols/paths from the architecture map) and read only the relevant views/models. Do not paste whole repo sections, tool logs, or accessibility trees into context; keep full logs on disk and cite short excerpts.
9. Batch related edits before building; rerun full regression suites at checkpoints, but never skip the one verification that establishes the fix.
10. During investigation explore freely; once a defect is understood, encode it as a deterministic test in the right layer (core, presentation, UI) instead of leaving a repeat-by-hand procedure.
11. Navigation, phase transitions, and accessibility shortcuts matter — keep the journey tested through the real `WorkspacePhase` flow, including DiskUnbloatUITests scenarios when window/picker behavior is at stake.
12. Never test destructive operations on real user data: cleanup tests use generated fixtures and either a recording/succeeding cleanup service or intentionally deleted fixture copies. Respect macOS privacy; TCC consent flows are only reset deliberately (`tccutil`) with the user's awareness.
13. Record results in `Documentation/VALIDATION.md` including unverified or environment-blocked checks. If runtime UI verification was needed but unavailable, say so instead of claiming it happened.

## Map-first product invariants

- Route screens using `WorkspacePhase`: choosing → scanning → preparing results → exploring. Launch and scanning must not mount the explorer's toolbar, map, or cleanup-queue panel. Cancelled/failed scans use dedicated outcomes; viewing a cancelled map requires opt-in and keeps cleanup disabled.
- Keep the map as the only results canvas; the cleanup queue is the sole side panel and opens automatically after a completed scan. There is no file browser or details inspector; curated descriptions appear only in the map hover card. Preserve the explorer's 960 × 640 minimum layout and accessibility shortcuts. The window follows the phase: chooser and scan screens are compact, and entering results restores the remembered full size; fullscreen frames are never resized programmatically.
- Build maps from bounded `MapScene` queries, never from a queue row. Account for all known bytes with atomic folders/aggregate tiles when depth, pixel, or entry budgets are reached. Do not collapse partial folders to zero. Keep legend highlighting independent of layout/filtering.
- Publish real stages/counters. The overall percentage is an approximation of the scanned volume's used data already read (discovered bytes versus the volume's used space measured once at scan start) and must stay labeled as approximate; never fabricate finer precision. Keep decorative animation independent of scanner updates, paused in inactive scenes, and compatible with Reduce Motion/Transparency. Do not delay short scans to show an animation.
- Quick targets must use the real user home and system-granted access, never container search paths as a substitute for the user's folders. Missing/revoked locations require picker authorization or a useful error, never additional entitlements or an implicit all-files grant.
- The app ships unsandboxed (macOS 27 denies other applications' app-data reads under the App Sandbox and later through the `SystemPolicyAppDataDetailed` policy consult with no consent dialog — sandboxing cannot be "prompted through", so the entitlement is replaced by TCC consent plus optional Full Disk Access). Full Disk Access is asked first and alone at every fresh scan start, and the offer gates the scan until the user answers; with the grant present no other consent fires, and without it the preflight raises the remaining folder/media consents in order before enumerating. Preflight refusal outcomes surface once as the `protectedFoldersRefused` scan signal; the issues sheet explains the Full Disk Access option instead of leaving per-path mystery errors, and its settings button lives in the sheet footer so the issue list stays readable. Denied paths stay honest scan issues.
- Grouped quick actions ("All caches", "Dev tools") scan several known home locations in one pass behind a synthetic group root (`ScanGroup.path`). They authorize through the home grant so every listed location is covered; missing members are skipped and listed as scan issues, and the scan fails only when no listed location is readable. The combined scope persists for post-cleanup rescans; refresh reruns the whole group for the wrapper and works inside any listed root otherwise. Cleanup keeps the full scope list, so boundaries still apply around every root. The wrapper itself is never removable or cleanable, but each listed root can be queued for in-place cleaning: its contents are removed and the folder stays.

## Refresh, analysis, and localization invariants

- Refresh branches through staging plus `ScanIndex.replaceBranch`; never remove live rows before a scan succeeds. Preserve raw sizes, identity groups, stable IDs/high-water allocation, revision invalidation, and overlapping-queue invalidation.
- The cleanup queue derives rows from normalized `CleanupEntry` values only; never derive queue totals from a map scene or a rendered row. The current open folder is listed by known size descending even with an empty queue; that listing is read-only context until an item is selected, and unselected containers expand to a lazy peek of their three largest children with honest paging. Map selection and panel rows mirror each other through the explorer's selection, never through the queue state. Filtering must not alter map geometry.
- Scanning reads directories in parallel with `getattrlistbulk`; bulk-read identity/fingerprint strings must stay byte-identical to `FileIdentity.read`. Summarized folders (packages without inspection, the "Measure as one item" list) are measured whole and stay atomic — never browsable, expandable, or summarized when they are the scan root.
- Curated rule matching is core SQL/domain behavior. Application activity and translated explanations are injected app adapters; unknown activity never means safe deletion. Recheck activity before each operation. Only the exact curated cache locations (and their contents) are exempt from managed-data protection; their parents and every other managed tree stay blocked, and the exemption travels on the cleanup plan. Items queued for deletion disappear from the map until they are removed from the queue or deleted.
- Quick-select recommendations come only from the closed `AutoSelectionSpec` list and apply within the scanned scope; proposals pass the same safety checks as manual selection (refusals are counted, never forced), the four levels nest (Junk ⊂ Caches ⊂ Rebuildable ⊂ Deep clean — every rule's junk coverage must nest inside its full coverage), every level above Junk warns with an honest estimate before selecting, and the deletion confirmations still gate deletion. "Long-unused" stays modification-based against `ScanOptions.longUnusedDays`, never access-date based. No level selects the single most recent version of a keep-newest location or the most recently used version of an app (a sole remaining version always survives); Deep clean's managed-data exemptions cover only the exact older-version folders it selected, never their app folder or siblings; installers are the only Downloads files any level takes; and user-authored content stored beside caches (LM Studio chats, conversations, presets) is never selected at any level — locations with mixed children carry a closed `eligibleChildNames` list, so unknown future children stay out until added deliberately.
- Native open-file events and drops share validation/authorization. Buffer cold-launch events; reject busy/multiple-location requests explicitly.
- Add every shipping string to English/Russian catalogs, including plural forms and accessibility. Translate labels only, never paths, IDs, or bookmarks. Run the localization audit and keep project resources/regions in sync.
